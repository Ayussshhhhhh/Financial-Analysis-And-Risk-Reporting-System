## 1. What This Project Is

This project is a batch analytics system for a lending business. It combines two related views:

1. **Financial performance:** revenue, costs, profit, balance sheet, and budget variance.
2. **Credit risk:** borrower default probability, credit scores, risk bands, and expected loss.

The system converts raw files into cleaned data, analytical tables, statistical results, and business-facing reports.

It is best understood as a portfolio and demonstration system. The loan portfolio is based on historical public data, while the general-ledger data is synthetic because the Kaggle dataset does not contain a company's internal accounting records.

## 2. The Main Pipeline

The executable pipeline is `src/automation.py`, run from the project root as a Python module:

```text
Kaggle loan archive + ledger CSV
              |
              v
        Data ingestion
              |
              v
       Cleaning and staging
              |
              +----------------------+
              |                      |
              v                      v
     Credit feature work      Financial calculations
              |                      |
              v                      v
       Credit scorecard       P&L, balance sheet,
       PD, scores, bands      budget variance
              |                      |
              +----------+-----------+
                         |
                         v
             Validation and reconciliation
                         |
                         v
              SQLite analytical database
                         |
                         v
              Excel, charts, HTML, PDF
```

Run the full process with:

```bash
python3 -m src.automation
```

Running `python3 src/automation.py` directly is not recommended because the script imports the project as the `src` package.

This is the input layer.

### `data/outputs/`

- `roc_curve.png`: model discrimination chart.

### `models/`

- `credit_scorecard.joblib`: serialized fitted scorecard.

### `data/reports/`

Excel reports generated by the current Python pipeline:

- `financial_report.xlsx`
- `balance_sheet_report.xlsx`
- `budget_variance_report.xlsx`
- `credit_risk_summary.xlsx`

### `reports/`

- `monthly_board_pack.html`
- `monthly_board_pack.pdf`

These are executive-style board-pack outputs generated by the orchestration module.

### `src/`

The implementation layer:

- `data_ingestion.py`: loads Kaggle data or generates fallback synthetic loans and ledger data.
- `data_cleaning.py`: standardizes fields, parses values, imputes missing values, derives default labels, and clips invalid ranges.
- `feature_engineering.py`: creates loan features and calculates WOE/IV diagnostics.
- `credit_scorecard.py`: trains logistic regression, converts PD to points, assigns risk bands, and calculates expected loss.
- `financial_calculations.py`: calculates P&L, balance sheet, and budget variance metrics.
- `validation.py`: runs accounting, model, coverage, and expected-loss checks.
- `reporting.py`: generates Excel reports.
- `automation.py`: coordinates the full process.

### `tests/`

Automated tests for data quality, financial calculations, and scorecard behavior.

### `notebooks/`

Five educational and analytical notebooks covering exploration, data preparation, financial analysis, scorecard development, and validation.

### `sql/`, `qlik/`, `excel/`, and `power_automate/`

These folders document the intended database, BI, spreadsheet, and distribution ecosystem. The active Python path writes a simpler pandas-derived SQLite structure directly; it does not execute every SQL script or deploy a live Qlik or Power Automate service.

## 4. Loan Data Lifecycle

### Ingestion

The loader recognizes the Kaggle accepted archive and supports both `.csv` and `.csv.gz` files. It:

- ignores rejected-loan files;
- maps Kaggle's `id` column to `loan_id`;
- reads only the needed fields to reduce memory use;
- preserves the historical loan statuses.

### Cleaning

The cleaning layer:

- converts terms such as `36 months` to numeric months;
- converts rates to numeric percentages;
- parses issue dates;
- imputes missing numeric and categorical values;
- removes duplicate loan IDs;
- derives the binary target `default_flag`;
- clips configured numeric ranges.

Default-label rules:

| Status | `default_flag` |
|---|---:|
| `Charged Off` | 1 |
| `Default` | 1 |
| `Fully Paid` | 0 |
| `Current`, `Late`, or other unresolved status | null |

Only rows with a known `default_flag` are used to train the scorecard.

## 5. Credit-Risk Model

The scorecard uses logistic regression with six numeric predictors:

- DTI
- annual income
- loan amount
- interest rate
- revolving utilization
- inquiries in the last six months

The model estimates probability of default:

```text
PD = probability that the loan defaults
```

PD is converted into scorecard points using the standard odds relationship:

```text
Score = Offset + Factor * ln((1 - PD) / PD)
```

Higher PD produces a lower score.

Expected loss is calculated as:

```text
Expected Loss = PD * LGD * EAD
```

Current assumptions:

- LGD: 45%
- EAD: loan amount
- Risk bands: Low, Medium, High, Very High

The current verified run produced:

- AUC: 0.6910
- Gini: 0.3821
- KS: 0.2763

These are useful demonstration results, but the current pipeline evaluates on the training data rather than a separate holdout sample. They should not be treated as production model-validation evidence.

## 6. Financial Analysis

The synthetic ledger contains monthly rows across regions, products, and departments. The financial layer calculates:

- Revenue and COGS
- Gross profit and gross margin
- Operating expenses
- EBITDA and EBIT
- Interest expense and tax
- Net profit and net margin
- Budget versus actual variance
- Favorable or unfavorable variance commentary
- Balance-sheet totals and the accounting identity

The accounting check is:

```text
Assets = Liabilities + Equity
```

The current ledger is illustrative rather than an actual ERP export.

## 9. Troubleshooting

### `ModuleNotFoundError: No module named 'src'`

Run the command from the project root using:

```bash
python3 -m src.automation
```

### No Kaggle file is found

Confirm the accepted file is inside `data/raw/` and is named either:

```text
accepted_2007_to_2018Q4.csv.gz
accepted_2007_to_2018Q4.csv
```

### The model uses fewer rows than the dataset

This is expected. Current, late, and other unresolved statuses do not have a final default outcome and are excluded from model training.

### Outputs look synthetic

The loan data is historical public data, but the general ledger is synthetic. Connect a real accounting or ERP source before using the financial reports for operational decisions.

## 10. Important Limitations

- The Lending Club data ends in 2018.
- The general ledger is synthetic.
- The scorecard currently uses raw numeric features; WOE/IV is calculated as a diagnostic but is not yet used to transform the model matrix.
- Model metrics are in-sample rather than holdout metrics.
- The Python database path is simpler than the documented SQL star schema.
- Risk-band thresholds are not fully consistent across all documentation and implementation surfaces.
- SQLite is appropriate for this local analytical workload, not a high-concurrency production warehouse.

These limitations do not prevent the project from running, but they matter when interpreting results or presenting the system as production-ready.
